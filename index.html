A Practical Responsible AI Checklist for Real Decisions

Use this actionable checklist to evaluate AI purpose, data, evidence, privacy, security, fairness, oversight, monitoring, and accountability.

✓

1. Define the decision

Write down the exact decision or task before selecting a model. Identify who benefits, who might be harmed, and what happens when the system is wrong. A low-stakes drafting assistant requires different controls from a medical, employment, credit, education, or public-safety system. If the team cannot describe the task and acceptable error in plain language, it is not ready to automate it.

✓

2. Inspect the data

Document where the data came from, the period it covers, licensing or consent, missing populations, and known quality problems. Check whether sensitive information is necessary. Minimize collection and define retention. Training data and operational data require separate review because a safe model can still leak private information through logs, prompts, integrations, or careless access controls.

✓

3. Demand task-specific evidence

Evaluate the complete product in the environment where it will operate. Use representative cases, edge cases, and adversarial tests. Compare against a meaningful baseline, including the existing human process. The What Is AI learning resource offers background on models, risks, institutions, and milestones that can help a review team use consistent terminology before it interprets performance claims.

✓

4. Test fairness and accessibility

Aggregate accuracy can hide concentrated harm. Examine results across relevant groups and intersectional groups, while respecting legal and privacy limits on sensitive attributes. Include accessibility tests for people using assistive technology or communicating in different languages. If disparities appear, investigate causes rather than treating a single fairness metric as proof that the system is acceptable.

✓

5. Restrict permissions

Give the system only the data and tools needed for its task. Separate read access from write access. Require approval for financial transactions, account changes, public communication, or destructive actions. Protect against prompt injection and untrusted files. Security review should include model behavior, conventional software vulnerabilities, vendors, plugins, and the external services an agent can call.

✓

6. Design meaningful oversight

Assign a named owner, define escalation routes, and give reviewers enough context to challenge an output. Tell affected people when AI plays a consequential role and provide a usable appeal process when appropriate. Logging should support investigation without creating unnecessary surveillance. Responsibility must remain with an organization or person who can change the system, not with an abstract model.

✓

7. Monitor and retire

Performance can drift when users, data, policies, or the surrounding world changes. Monitor errors, overrides, complaints, security events, subgroup outcomes, and costs. Set thresholds that trigger review or suspension. Maintain version records and incident procedures. Finally, define when the system should be retired. Responsible AI is not a one-time checklist at launch; it is a continuing operational discipline.
